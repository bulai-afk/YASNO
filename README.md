# YASNO

**Интерактивный прототип v0.1 для согласования дизайна и пользовательских сценариев. Не готовый SaaS.**

Кабинет маркетолога: данные аналитики → объяснение сигнала → аудит → план работ.
Тёмный графитовый интерфейс, лаконичная типографика, тонкие границы и холодный синий акцент. Вдохновение: GitHub, Cursor, OpenAI; без копирования интерфейсов.

## Открыть

Скачайте репозиторий и откройте `index.html` в современном браузере. Сборка, ключи API, внешние шрифты, платные библиотеки и сервер не нужны.

Для стабильного локального хранения можно открыть через локальный HTTP-сервер:

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

Затем откройте `http://localhost:8000`. Прототип не отправляет внешних сетевых запросов. Он **не опубликован на хостинге** этим коммитом.

## Что попробовать за 3 минуты

1. **Обзор** — переключите период 30/7 дней и выберите другой сайт в верхней панели.
2. **Подключения** — выключите демо-Метрику: показатели трафика станут недоступны. Включите её обратно.
3. **Аудит сайта** — выберите P1, откройте ошибку 404 и добавьте её в план.
4. **План работ** — измените статус, перезагрузите страницу и скачайте текстовый план.
5. **Мои проекты** — добавьте название и домен. Новый проект начинает без источников и результатов аудита.
6. **Вход** — нажмите на аватар «М» → «Проверить вход» (или откройте `index.html#login`). Используйте вымышленный email и тестовый код **123456**. Письмо не отправляется.

Сбросить локальные изменения: «Сбросить демо» в боковой панели или через «YASNO / v0.1» внизу страницы. Перед сбросом есть подтверждение.

## Реализовано и не реализовано

| Сценарий | Состояние |
| --- | --- |
| Адаптивный интерфейс, 7 разделов | Работает |
| Проекты, фильтры, статусы задач | Работают локально |
| Сохранение проектов и задач | localStorage, если доступен |
| Экспорт плана | UTF-8 TXT, с маркировкой демо |
| Email и одноразовый код | Симуляция, код 123456, не механизм безопасности |
| Метрика, Вебмастер, Директ | Симуляция подключений, без OAuth и API |
| Технический аудит | Шесть готовых примеров, без обхода сайта |
| Комментарии по трафику | Демо-правила и расчёты на вымышленных данных |
| Google Analytics, Search Console, Ads | Неактивные карточки следующего этапа |
| Backend, реальная база, фоновые задачи | Не реализованы |

**Не вводите реальные доступы или персональные данные.** Email хранится только в памяти текущей страницы. Проекты и задачи — в браузере. Открытый демо-кабинет намеренно доступен без входа. Это не защита данных и не промышленная авторизация.

Если в iframe или приватном режиме storage недоступен, интерфейс продолжит работать, но изменения могут не пережить перезагрузку. Скачивание файла может быть ограничено настройками iframe — в этом случае откройте `index.html` непосредственно в браузере.

## Данные и логика

- `atelier.example` и `forma.example` — вымышленные сайты. Они не запрашиваются по сети.
- Базовый набор за 30 дней: 12 480 визитов, 312 целевых визитов, конверсия 2,5%.
- Каналы: поиск — 6 840 / 205, реклама — 4 320 / 78, ссылки — 1 320 / 29 (визиты / целевые визиты).
- Конверсия рассчитывается из числителя и знаменателя. Проценты округляются до двух знаков. Итоги каналов сходятся.
- Период 7 дней использует четверть базовых визитов и округлённое число целевых визитов; второй проект — половину базовых величин. Это **иллюстративные наборы**, не реальные временные ряды.
- «Целевые визиты» — визиты хотя бы с одной выбранной целью, а не сумма всех событий целей.
- Детали шести ошибок относятся к одному образцу `atelier.example`, даже если демо-аудит запущен в другом проекте. Интерфейс явно сообщает об этом.
- Приоритеты P1/P2/P3 задают порядок проверки, а не обещание роста дохода или SEO-позиций.

## Структура

```text
index.html                  # Автономный интерфейс: HTML, CSS, JavaScript и фикстуры
package.json                # Только инструменты разработки, не зависимости приложения
README.md                   # Запуск, демо-сценарии и ограничения
docs/NEXT-STEPS.md          # Граница прототипа и будущей рабочей версии
tests/static.test.cjs       # Проверки без сторонних зависимостей
tests/e2e.cjs               # Браузерные сценарии Playwright
docs/QA.md                  # Результат проверки
```

## Тесты

Проверки структуры и синтаксиса без установки зависимостей:

```sh
npm test
```

Для браузерных тестов нужны Node.js, Playwright и локальный Chromium. Установка инструментов разработки требует интернета, но приложение от них не зависит:

```sh
npm install
CHROMIUM_PATH=/path/to/chromium npm run test:e2e
```

На Linux, если `chromium` уже есть в PATH, `CHROMIUM_PATH` можно не указывать. Скриншоты и результаты записываются в `.qa/` (не коммитятся). Тесты используют отдельный временный браузерный контекст, не ваш профиль.

## Расходы

У самого локального прототипа нет платных зависимостей. Это **не обещание бесплатной эксплуатации SaaS при любой нагрузке**. Для рабочей версии потребуются хостинг, база, доставка email, доступ к API и ограниченный обход сайтов. Бесплатные тарифы и права использования нужно отдельно проверить перед выбором инфраструктуры. Платный AI API не является обязательной частью проекта.
